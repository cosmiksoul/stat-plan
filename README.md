# stat·plan — A/B planner без сюрпризов

Открытый клиентский инструмент для планирования и валидации A/B-тестов. Помогает продуктовому менеджеру пройти полный цикл — от формулировки гипотезы до пост-анализа — без необходимости вручную выбирать статистический критерий и без риска получить методологически сломанный тест.

**Все данные хранятся локально на компьютере пользователя.** Нет бэкенда, логина, истории тестов. Артефакты — обычные `.md` / `.ipynb` / `.csv` / `.html` / `.zip`.

🔗 **Открыть:** [GitHub Pages deployment](https://your-org.github.io/stat-plan/) (если задеплоено).

## Зачем

A/B-калькуляторов в интернете много, но почти все упираются в две проблемы:

1. **Методологическая слепота калькулятора.** Не знает про right-skewed распределения, zero-inflation в ARPU, sample ratio mismatch — и спокойно предлагает t-test там, где нужен Welch или bootstrap CI.
2. **Высокий порог входа.** Чтобы корректно выбрать критерий, понять допущения и оценить мощность, пользователю нужно отлично знать прикладную статистику.

stat·plan закрывает обе проблемы через **дерево вопросов с минимальным ветвлением**, **структурную оценку плана** и **генерируемый Jupyter-ноутбук** с правильным набором проверок под конкретный сценарий.

## Флоу из 4 шагов

| Шаг | Что происходит | Артефакт на выходе |
|---|---|---|
| **01 Бриф** | 10 вопросов: гипотеза → метрика → baseline → MDE → трафик → guardrails → decision rules. Live-расчёт sample size. Опц. Data Peek для уточнения baseline и σ. | внутреннее состояние |
| **02 Тест-план** | Preview `test_plan.md` + оценка 0-100 по 4 группам критериев. Можно скачать, отдать аналитику, получить обратно edited версию. | `test_plan.md` |
| **03 Конструктор** | Выбор ячеек ноутбука + editable schema под имена колонок в твоём warehouse. | `analysis.ipynb` |
| **04 Валидация и отчёт** | Перетащи выполненный ноутбук — парсер достанет результаты и графики. Автоматические проверки (SRM, sample size vs план, направление), применение decision rules, самодостаточный HTML-отчёт. | `report.html`, `readout.md`, `analysis.zip` |

**Ключевая идея:** stat·plan **не пересчитывает** статистику — это была бы циркулярная валидация. Считает один раз в ноутбуке у пользователя, а потом помогает корректно интерпретировать.

## Для кого

- **Продуктовые менеджеры** — заполняют бриф, получают тест-план и готовый ноутбук, идут обсуждать с аналитиком, интерпретируют результат
- **Аналитики** — получают структурированный артефакт для ревью, могут править md-файл и возвращать PM-у
- **Небольшие команды без штатного аналитика** — получают разумные методологические дефолты и предупреждения о подозрительных решениях

**Не целим:** data scientist-ов с продвинутыми методологическими запросами (sequential testing, causal inference), enterprise-команды с собственной A/B-платформой.

## Принципы

1. **No backend.** Всё в браузере. localStorage хранит активный тест, после restart — чистый стейт.
2. **Артефакты — обычные файлы.** Md, ipynb, csv, html, zip. Можно открыть, отредактировать, закоммитить в git.
3. **Тул не принимает продуктовых решений.** Не говорит «катить или нет». Финальное решение всегда за человеком (ADR-004).
4. **Структурная оценка.** Скоринг проверяет полноту секций и консистентность методов. Не оценивает «хороша ли продуктовая гипотеза».
5. **Открытость данных и правил.** Все формулы расчётов задокументированы в `/docs/methodology`.
6. **Минимум ветвлений в брифе.** 10 вопросов, дефолты везде где разумно. Сложности (α/power, CUPED) спрятаны в «продвинутые параметры».

## Что НЕ делаем — намеренно

- ❌ Не интегрируемся с BigQuery / Amplitude / Mixpanel — пользователь сам выгружает CSV
- ❌ Не храним историю тестов — каждый прогон stateless
- ❌ Не делаем sequential testing / mSPRT в v1 — кандидат на v2
- ❌ Не делаем библиотеку прошлых тестов — это уже SaaS, выходит за scope
- ❌ Не используем LLM в продакшен-флоу — все правила детерминированные и проверяемые
- ❌ Не пересчитываем Δ/p/CI из CSV — circular validation против наших же багов не защищает

Полное обоснование — в `/docs/methodology` раздел «Что мы НЕ делаем».

## Технический стек

- **React 19 + Vite + Tailwind v4 + react-router-dom v7** (HashRouter)
- **Vitest 4** для unit-тестов math/parse-логики (467 тестов)
- **Deps:** js-yaml (YAML parsing), papaparse (CSV, lazy), recharts (histogram, lazy), JSZip (export bundle, lazy)
- **Деплой:** GitHub Pages через GitHub Actions из `main`
- **Bundle:** initial ~136 KB gzip, лениво подгружаемые chunks для Data Peek и /step4

Pyodide отвергнут — 10MB рантайма ради scipy не оправданы (ADR-009).
