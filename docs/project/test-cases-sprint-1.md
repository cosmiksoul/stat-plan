# Test Cases Sprint 1 — Foundation + Start Screen + Step 1 Skeleton

**Дата подготовки:** 2026-05-15
**Тестируемый URL:** `https://cosmiksoul.github.io/stat-plan/`
**Локально:** `http://localhost:5173/stat-plan/` после `npm run dev`

---

## Как пользоваться

1. Открываешь URL в браузере, проходишь кейсы по порядку.
2. Каждому кейсу проставляешь статус: `ok` (работает как ожидалось), `bug` (что-то не так), `skip` (не смог проверить — например, нет Safari).
3. Если `bug` — описываешь в таблице ниже (раздел Bugs found) с severity и шагами воспроизведения.

**Severity:** Critical / High / Medium / Low (см. Dev-Cycle.md фаза 6).

**На что обратить особое внимание** (в code review поднимались 🟡 concerns): кейсы 5, 11, 12, 15 — там высокая вероятность найти runtime-проблемы.

## Что НЕ тестируем в этом спринте

Зафиксировано, чтобы не было соблазна расширить:

- **Парсинг загруженного `test_plan.md`** — будет в Sprint 2/3, сейчас только сообщение-заглушка.
- **localStorage сохранение state'а** — отдельная задача, не в скоупе Sprint 1.
- **Содержимое тур-плашек** — Sprint 1 делал только toggle класса, плашек как таковых нет.
- **Реальные вопросы брифа** — placeholder.
- **Шаги 2-5** — заблокированы, страниц нет.
- **Sample size / scoring / графики / экспорт** — другие спринты.
- **Полноценный mobile UX и A11y-аудит** — Known Issues в sprint-report.

Если в QA найдётся проблема в любой из этих областей — это **не bug Sprint 1**, а либо отложенная функциональность, либо новая user story в JTBD.
